# 1. アプリ概要

## 1.1 目的

「待機列整理アプリ」は、YouTubeライブ配信中のチャットを取得し、配信者が指定した文言に反応して、参加希望者の待機列を自動整理するローカル配信支援アプリである。

OBS上には、現在参加中のユーザー、次回参加予定のユーザー、待機中の人数またはグループ数、受付状態などを表示する。

配信者は管理画面から、受付開始・受付終了、次の参加者への進行、手動追加、手動削除、並び替えなどを行える。

## 1.2 基本コンセプト

```text
YouTubeライブチャットに流れた「参加希望」などの文言を検知し、
参加者の順番待ちを自動で整理して、OBSに見やすく表示する。
```

## 1.3 想定用途

本アプリは、以下のような参加型配信での利用を想定する。

* 参加型ゲーム配信
* 参加型麻雀配信
* 配信者を含めて4人で遊ぶゲーム配信
* 視聴者3人を1グループとして扱う順番待ち企画
* 先着順を基本にしつつ、参加回数の少ない視聴者を優先したい配信
* 配信中に受付状態を画面表示したい企画
* 手動管理では参加者の見落としが発生しやすい企画

## 1.4 非対象

以下は初期版の対象外とする。

* 抽選による参加者選定
* 複数配信プラットフォーム同時対応
* クラウド同期
* 複数PC間でのリアルタイム共有
* スマートフォン単体での管理
* OBSネイティブプラグインとしての実装
* 視聴者側参加人数の可変設定
* 金銭や賭けを伴う用途

# 2. 全体構成

## 2.1 推奨構成

初期版は、OBSネイティブプラグインではなく、以下の構成とする。

```text
YouTube Live Chat
  ↓
ローカルアプリ
  ↓
ローカルDB
  ↓
OBS表示用オーバーレイ
  ↓
OBSブラウザソース
```

## 2.2 画面構成

| 画面      | 用途                              |
| ------- | ------------------------------- |
| 管理画面    | 配信者または配信補助者が操作する画面              |
| OBS表示画面 | 配信画面に載せるオーバーレイ画面                |
| 設定画面    | 検知ワード、グループ人数、表示形式、接続情報などを設定する画面 |
| ログ画面    | 参加、取消、手動操作、エラーなどの履歴を確認する画面      |

## 2.3 実装方式

初期版では、ローカルWebアプリ方式を採用する。

```text
管理画面: http://localhost:8080/control
OBS表示: http://localhost:8080/overlay
設定画面: http://localhost:8080/settings
```

OBSにはブラウザソースとして `http://localhost:8080/overlay` を読み込ませる。

# 3. 用語定義

| ------ | ------------------------ |
| 参加希望   | 視聴者がチャット上で参加意思を示すこと      |

| 手動削除   | 管理画面から配信者がユーザーを削除すること    |

# 4. 基本機能

## 4.1 YouTubeライブチャット取得

YouTubeライブ配信のチャットを取得し、投稿されたメッセージを順次処理する。

チャット取得方式は、初期版ではAPIキー利用を必須としない。

MVPでは、`pytchat` または `chat-downloader` などのローカル実行向けチャット取得ライブラリを候補とし、検証時点で安定して動作する方式を採用する。

ただし、これらはYouTube公式APIそのものではないため、YouTube側の仕様変更により動作しなくなる可能性がある。

そのため、実装上はチャット取得処理を `ChatProvider` として抽象化し、将来的に以下を差し替え可能にする。

* pytchat方式
* chat-downloader方式
* YouTube Data API v3方式
* その他の取得方式

公式APIを使う場合は、`pollingIntervalMillis` に従って取得間隔を制御し、過剰なポーリングを行わない。

取得対象の主な情報は以下とする。

| 項目                | 用途                  |
| ----------------- | ------------------- |
| messageId         | 同一メッセージの重複処理防止      |
| publishedAt       | 受付順の判定              |
| displayMessage    | 判定対象となるチャット本文       |
| authorChannelId   | 同一ユーザー判定            |
| authorDisplayName | OBS表示名、管理画面表示名      |
| profileImageUrl   | 将来的なアイコン表示用         |
| isChatOwner       | 配信者本人判定、除外設定用       |
| isChatModerator   | モデレーター判定、除外または強調表示用 |
| isChatSponsor     | メンバー判定、将来的な表示強調用    |

## 4.2 参加希望ワード検知

配信者が設定した参加希望ワードをチャット本文から検知する。

初期設定例は以下とする。

```text
参加希望
参加します
参加したい
予約
はいります
入ります
```

## 4.3 取消ワード検知

配信者が設定した取消ワードをチャット本文から検知する。

初期設定例は以下とする。

```text
参加取消
参加希望取消
参加希望取り消し
取り消し
キャンセル
辞退
```

## 4.4 待機列管理

参加希望者を受付順に待機列へ追加する。

基本ルールは以下とする。

* 同一ユーザー判定は `authorChannelId` を基準とする
* 表示名は最新の `authorDisplayName` を使用する
* 参加希望者は受付順に並べる
* 受付終了中の参加希望は待機列へ追加しない
* 取消ワードを検知した場合、該当ユーザーを待機列から削除する
* 管理画面から手動で追加・削除・並び替えできる

## 4.5 OBS表示

OBSブラウザソースに表示する画面を提供する。

表示する基本項目は以下とする。

* タイトル
* 受付状態
* 現在参加中
* 次回参加予定
* 待機人数
* 待機グループ数
* 必要に応じた補足メッセージ

なお、ユーザーごとの参加消化回数、対局参加回数は配信画面上には表示しない。

参加消化回数は、あくまで配信者側の管理画面で確認するための内部情報として扱う。

## 4.6 管理画面操作

管理画面では、以下の操作を行える。

| 操作           | 必須度 | 内容                                        |
| ------------ | --: | ----------------------------------------- |
| 受付開始         |   高 | 参加希望ワードの受付を開始する                           |
| 受付終了         |   高 | 新規参加希望の受付を停止する                            |
| 次へ進める        |   高 | 次回参加予定を現在参加中へ移動する                         |
| 手動追加         |   高 | ユーザー名を指定して待機列に追加する                        |
| 手動削除         |   高 | 指定ユーザーを待機列または現在参加中から削除する                  |
| 並び替え         |   中 | 待機列内の順番を変更する                              |
| 消化回数修正       |   中 | ユーザーごとの消化回数を修正する                          |
| 表示名変更        |   中 | OBS上の表示名を手動で上書きする                         |
| ひとつ戻す        |   中 | 直前操作を取り消す                                 |
| 全リセット        |   高 | 現在参加中・待機列を初期化する                           |
| 低消化回数優先モード切替 |   高 | 参加回数、対局参加回数の少ないユーザーを優先的に次回参加予定へ入れるかを切り替える |
| 簡易手動並び替え     |   高 | 上下ボタンで待機列の順番を調整する                         |
| テスト用参加者投入    |   高 | OBSレイアウト確認用のダミー参加者を生成する                   |
| ログ出力         |   低 | 参加履歴や操作履歴をCSV等で出力する                       |

# 5. 待機列仕様

## 5.1 基本モード

初期版では、視聴者3人を1グループとして扱う固定モードのみを対象とする。

```text
配信者 1人 + 視聴者 3人 = 合計4人
```

そのため、1人参加モードや任意人数グループ機能は初期版では実装しない。

## 5.2 グループ人数

グループ人数は、視聴者3人で固定する。

設定画面での人数変更機能は不要とする。

```text
現在参加中: 最大3人
次回参加予定: 最大3人
1グループ: 視聴者3人
```

## 5.3 表示分類

OBS表示上では、待機列を以下に分類して表示する。

```text
現在参加中
次回参加予定
待機中
```

表示例は以下とする。

```text
現在参加中
Aさん / Bさん / Cさん

次回参加予定
Dさん / Eさん / Fさん

待機中
あと2グループ

受付中
```

## 5.4 参加希望時の処理

ユーザーが参加希望ワードを送信した場合、以下の順で処理する。

1. メッセージIDの重複確認
2. 投稿者のユーザーIDを取得
3. 受付状態を確認
4. 検知ワードに一致するか判定
5. 既に待機列または現在参加中にいるか確認
6. 条件に応じて追加、並び直し、または無視する
7. OBS表示を更新する
8. ログに記録する

## 5.5 同一ユーザーが再度参加希望した場合

同一ユーザーが既に待機列にいる状態で再度参加希望ワードを送信した場合は、以下の仕様とする。

```text
既存の待機予約を削除し、最後尾へ並び直す。
```

例：

```text
変更前:
A / B / C / D / E

Bさんが再度「参加希望」

変更後:
A / C / D / E / B
```

この仕様により、再送信による割り込みは発生しない。

## 5.6 現在参加中ユーザーが再度参加希望した場合

現在参加中のユーザーが再度参加希望ワードを送信した場合、以下の仕様とする。

```text
現在参加中の状態は維持し、次回以降の再参加予約として最後尾に追加する。
```

ただし、既に待機列にも存在している場合は、その待機予約を削除して最後尾へ移動する。

## 5.7 受付終了中の参加希望

受付終了中に参加希望ワードを検知した場合、以下の処理とする。

* 待機列には追加しない
* OBS表示には反映しない
* 管理画面には通知する
* ログには「受付終了中の参加希望」として記録する

## 5.8 取消時の処理

ユーザーが取消ワードを送信した場合、以下の処理とする。

| 状態        | 処理                       |
| --------- | ------------------------ |
| 待機列にいる    | 待機列から削除する                |
| 次回参加予定にいる | 削除し、後続を繰り上げる             |
| 現在参加中にいる  | 原則として自動削除しない。管理画面で手動対応する |
| どこにもいない   | 何もしない。ログのみ残すことは可能        |

## 5.9 低消化回数優先モード

管理画面に「低消化回数優先モード」のチェックボタンを設ける。

このモードは、参加回数、対局参加回数が少ないユーザーを、次回参加予定の範囲内で優先的に参加させるための機能である。

### 5.9.1 モードOFFの場合

通常の先着順で待機列に追加する。

```text
新規参加希望者は、常に待機列の最後尾に追加される。
```

### 5.9.2 モードONの場合

新たに参加希望したユーザーの参加回数が、次回参加予定に入っているユーザーより少ない場合、次回参加予定の範囲へ割り込める。

ただし、割り込みによって次回参加予定から外れるユーザーは、次回参加予定内で最も参加希望が遅かったユーザーとする。

### 5.9.3 判定例

前提：視聴者3人固定の場合。

```text
現在参加中
Aさん / Bさん / Cさん

次回参加予定
Dさん 2回目予定
Eさん 2回目予定
Fさん 2回目予定

待機列
Gさん / Hさん
```

ここで、参加回数0回のXさんが参加希望した場合：

```text
次回参加予定
Dさん / Eさん / Xさん

待機列
Fさん / Gさん / Hさん
```

この場合、Dさん・Eさん・Fさんはいずれも同じ参加回数であるため、次回参加予定の中で参加希望が最も遅かったFさんが繰り下げ対象となる。

### 5.9.4 割り込み条件

割り込み条件は以下とする。

1. 低消化回数優先モードがONである
2. 新規参加希望者が現在参加中ではない
3. 新規参加希望者の参加回数が、次回参加予定内の少なくとも1人より少ない
4. 次回参加予定が既に3人で埋まっている
5. 新規参加希望者が40秒状態変更ロック中ではない

上記を満たす場合、新規参加希望者は次回参加予定に入る。

繰り下げ対象は、次回参加予定内で以下の条件により決定する。

1. 新規参加希望者より参加回数が多いユーザーを候補にする
2. 候補が複数いる場合、参加希望時刻が最も遅いユーザーを繰り下げる
3. 繰り下げられたユーザーは、待機列の先頭に移動する

### 5.9.5 注意点

この機能は、完全な抽選や自動公平化ではなく、参加回数の少ない人を次回枠に入りやすくするための補助機能である。

そのため、管理画面から手動で順番を調整できる余地は残す。

## 5.10 40秒状態変更ロック

同一ユーザーによる短時間の参加・取消スパムを防ぐため、状態変更後40秒間は同一ユーザーの再状態変更をロックする。

対象となる状態変更は以下とする。

* 参加希望から辞退
* 辞退から再度参加希望
* 参加希望の再送による並び直し
* 取消の連投

### 5.10.1 基本仕様

```text
同一ユーザーが参加希望または取消によって状態変更された場合、
その時刻から40秒間、次の状態変更を無効にする。
```

40秒以内に再度対象ワードを送信した場合は、以下の処理とする。

* 待機列は変更しない
* OBS表示には反映しない
* 管理画面ログには「ロック中の操作」として記録する
* 必要に応じて管理画面にのみ通知する

### 5.10.2 例

```text
00:00 Aさん 参加希望 → 受付
00:20 Aさん 取消 → ロック中のため無効
00:41 Aさん 取消 → 有効
```

```text
00:00 Aさん 取消 → 受付
00:15 Aさん 参加希望 → ロック中のため無効
00:41 Aさん 参加希望 → 有効
```

## 5.11 OBS表示名の制限

YouTubeの表示名には、長い文字列、絵文字、環境依存文字が含まれる場合がある。

OBS表示の崩れを防ぐため、OBS表示画面では以下の制御を行う。

* 表示名は最大15文字程度を目安に省略表示する
* CSSで `text-overflow: ellipsis;` を使用する
* 折り返しによるレイアウト崩れを防ぐ
* 管理画面では元の表示名を確認できるようにする
* 必要に応じて表示名を手動上書きできるようにする

# 6. 進行管理仕様

## 6.1 「次へ進める」ボタン

管理画面に「次へ進める」ボタンを配置する。

このボタンを押すと、以下の処理を行う。

1. 現在参加中のユーザーの消化回数を加算する
2. 次回参加予定のユーザーまたはグループを現在参加中へ移動する
3. 待機列から次のユーザーまたはグループを次回参加予定として表示する
4. OBS表示を更新する
5. 操作ログに記録する

## 6.2 初回開始時

まだ現在参加中が空の場合、「次へ進める」ボタンを押すと、最初の参加者または最初のグループを現在参加中へ移動する。

## 6.3 次回参加予定が不足している場合

次回参加予定人数が3人に満たない場合も表示する。

例：

```text
次回参加予定
1. Aさん
2. Bさん
3. 参加者募集中
```

不足枠の表示文言は以下で固定する。

```text
参加者募集中
```

## 6.4 参加者3名未満で「次へ進める」を押した場合

参加者が3名未満でも、「次へ進める」ボタンによって現在参加中へ移動できる。

この場合、参加表明済みメンバーの名前と、不足枠として「参加者募集中」を表示する。

例：

```text
次回参加予定
1. Aさん
2. Bさん
3. 参加者募集中
```

この状態で「次へ進める」を押した場合：

```text
現在参加中
1. Aさん
2. Bさん
3. 参加者募集中
```

この不足枠はクローズせず、受付中であれば後続の参加希望者を現在参加中の空き枠へ補充できるものとする。

## 6.5 参加者が来ない場合

参加者が不在、反応なし、辞退などの場合は、管理画面から手動削除する。

自動スキップ機能は初期版では必須としない。

# 7. 画面仕様

## 7.1 OBS表示画面

OBS表示画面は、配信に映る前提で作成する。

初期CSSでは、OBSブラウザソースでそのまま使用できるように、背景透過を標準とする。

```css
body {
  background-color: transparent;
}

.name {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

必要に応じて、カラーキー用背景色を設定できる余地は残す。

初期表示例は以下とする。

```text
待機列整理アプリ

受付中

現在参加中
1. Aさん
2. Bさん
3. Cさん

次回参加予定
1. Dさん
2. Eさん
3. Fさん

待機中
あと2グループ / 7人
```

3人未満の場合は以下のように表示する。

```text
現在参加中
1. Aさん
2. Bさん
3. 参加者募集中
```

## 7.2 OBS表示項目

| 項目          |   初期版 | 備考                    |
| ----------- | ----: | --------------------- |
| アプリ名またはタイトル |    必須 | 表示/非表示を切替可能にする        |
| 受付状態        |    必須 | 受付中 / 受付終了            |
| 現在参加中       |    必須 | 個人またはグループ             |
| 次回参加予定      |    必須 | 個人またはグループ             |
| 待機人数        |    必須 | 人数表示                  |
| 待機グループ数     |    必須 | グループモード時に表示           |

# 8. チャット判定仕様

## 8.1 判定方式

初期版では、以下の判定方式を採用する。

| 判定方式     |  初期対応 | 内容                     |
| -------- | ----: | ---------------------- |
| 完全一致     |    対応 | チャット本文が設定ワードと一致した場合に検知 |
| 前方一致     |    対応 | チャット本文が設定ワードから始まる場合に検知 |
| 前後空白無視   |    対応 | 前後のスペースを除去して判定         |
| 大文字小文字無視 |    対応 | 英字の大小を区別しない            |
| 全角半角正規化  |    対応 | 可能な範囲で表記ゆれを吸収          |
| 部分一致     | 初期OFF | 誤検知の可能性があるため初期状態では使わない |
| 正規表現     |   後回し | 上級者向け設定としてPhase 2以降    |
| 絵文字除去    |   後回し | 必要に応じて追加               |

## 8.2 初期推奨

初期状態では、以下を採用する。

```text
完全一致 + 前方一致 + 前後空白無視 + 全角半角正規化
```

例：

```text
参加希望
参加希望です
参加希望！
参加希望 お願いします
```

上記は検知対象とする。

一方で、文中に参加希望ワードが含まれるだけのケースは初期状態では検知しない。

理由は、部分一致を初期状態で有効にすると、雑談中の文脈まで拾う可能性があるためである。

## 8.3 誤検知対策

誤検知対策として、以下を用意する。

* 参加希望ワードの編集
* 取消ワードの編集
* NGワード設定
* 配信者本人のコメント除外
* モデレーターのコメント除外
* 40秒状態変更ロック
* 管理画面での手動取り消し
* 操作ログからの復元

# 10. 例外処理

## 10.1 同名ユーザー

同名ユーザーが存在する場合も、`authorChannelId` を基準に別ユーザーとして扱う。

OBS表示上で区別できない場合は、管理画面で表示名を手動変更できるようにする。

## 10.2 表示名変更

ユーザーがYouTube上の表示名を変更した場合、最新の表示名に更新する。

ただし、手動上書き表示名が設定されている場合は、OBS表示では手動上書き名を優先する。

## 10.3 アプリ再起動

アプリ再起動時には、SQLiteから以下を復元する。

* 受付状態
* 現在参加中
* 待機列
* ユーザーごとの消化回数
* 設定情報

## 10.4 YouTube API切断

YouTube APIとの接続が切断された場合、以下の処理を行う。

* 管理画面に接続エラーを表示する
* 自動再接続を試行する
* OBS表示は最後の状態を維持する
* 復旧後、未処理メッセージを可能な範囲で取得する

## 10.5 OBS表示停止

OBS表示が更新されない場合に備え、管理画面に以下を用意する。

* 表示更新ボタン
* オーバーレイURL再読み込み案内
* 接続状態表示

## 10.6 操作ミス

操作ミスに備え、Phase 2までに「ひとつ戻す」機能を実装する。

初期版では、ログを確認して手動復旧する運用でも可とする。

# 15. 初期仕様としての完成形

現時点では、以下の仕様を初期方針とする。

```text
待機列整理アプリは、YouTubeライブチャットと連携し、
指定された参加希望ワードを検知した場合、
投稿者のYouTubeチャンネルIDを基準に待機列へ追加する。

待機列は、視聴者3人を1グループとして管理する。

OBSブラウザソース上には、
「現在参加中」「次回参加予定」「待機人数」「待機グループ数」「受付状態」を表示する。

参加者が3人未満の場合は、不足枠に「参加者募集中」と表示する。

同一ユーザーが再度参加希望を送った場合、
既存の待機予約を削除し、最後尾へ並び直す。

参加取消ワードを送った場合、
待機列から削除し、後続参加者を繰り上げる。

配信者は管理画面から「次へ進める」を押すことで、
次回参加予定者を現在参加中へ移動できる。

各ユーザーの参加消化回数はローカルDBに保存し、
配信画面には表示せず、管理画面でのみ確認できるようにする。

低消化回数優先モードがONの場合、
新規参加希望者の参加消化回数が次回参加予定者より少なければ、
次回参加予定枠へ割り込める。

このとき、次回参加予定から繰り下げられるのは、
割り込み対象候補の中で参加希望時刻が最も遅いユーザーとする。
```

# 16. 判断

本アプリは、OBSネイティブプラグインとして作るよりも、ローカルWebアプリとして作り、OBSブラウザソースで表示する構成が現実的である。

理由は以下である。

* OBSネイティブプラグインは開発難度が高い
* ローカルWebアプリならHTML/CSS/JavaScriptで表示を作りやすい
* OBSブラウザソースとの相性が良い
* 管理画面と表示画面を分離できる
* 将来的にElectronやTauriで配布アプリ化しやすい

したがって、初期開発では以下の方針を採用する。

```text
ローカルWebアプリ + SQLite + OBSブラウザソース
```

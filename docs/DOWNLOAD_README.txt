参加型整列プラグイン 1.1.1 — はじめに

このアプリは、参加型配信の参加者を3人ずつ整理し、OBSに待機列を表示するWindows用アプリです。

■ まずは起動
1. このプロジェクトのGitHub Releasesから取得したZIPを右クリックし「プロパティ」を開きます。
2. 「全般」の下部に「許可する」がある場合はチェックして「適用」→「OK」を押します。項目がなければそのまま進みます。
3. ZIPを右クリックし「すべて展開」を選びます。
4. 展開したフォルダー内の「参加型整列プラグイン.exe」を開きます。
5. 初回案内に従ってOBSへ表示を追加します。

Windows 11 x64向けです。Microsoft Edge WebView2 Runtimeを使用します。
Chrome・Python・OBS追加プラグインのインストールは不要です。
WebView2が不足する場合の公式ページ：
https://developer.microsoft.com/microsoft-edge/webview2/

exeだけを移動せず、_internalを含むフォルダー全体を保管してください。
_internalは起動に必要なファイルです。THIRD_PARTY_LICENSESとTHIRD_PARTY_NOTICES.jsonは使用ライブラリのライセンス情報です。

■ OBSに表示する
1. アプリ上部の「OBSに追加する」を開き、「表示URLをコピー」を押します。
2. OBSの「ソース」の＋から「ブラウザ」を追加します。
3. 「ローカルファイル」をオフにし、URLを貼り付けます。
4. 初期設定では幅480・高さ600にします。
5. OBSのプレビューで位置と大きさを調整します。

背景は透過されます。次回も同じブラウザソースを使えます。
「管理用URL」はアプリ操作用です。配信用ソースには貼り付けないでください。
OBSで管理画面を開きたい場合は、「管理用URL」をカスタムブラウザドックに登録します。

■ 参加者を管理する
・「参加者の追加・検索」で名前を入力して追加します。
・NOWは現在の参加者、NEXTは次の3人、QUEUEはその後の待機者です。
・対戦終了時に「次の対戦へ」を押すと、交代して対戦回数が増えます。
・「受付を開始／終了」で参加受付を切り替えます。
・参加者一覧の「編集」で表示用の申告名を変更できます。「削除」は対象名を確認後に一覧から外します。参加回数と記録済み履歴は残ります。
・参加者を右クリックすると削除や回数補正などを行えます。
・管理画面の「待機中の参加者」に全員が参加順で並びます。先頭3人は「次」の目印が付きます。
・行をドラッグして順番を変更できます。移動先の行の上半分／下半分で前／後ろへ挿入します。
・「編集」で表示用の名前（申告名）を変更・保存できます。OBSに出すには表示設定で申告名を含む方式を選びます。
・初回参加優先モードは、参加回数が少ない方を優先します。
・「直前の操作を戻す」で直前の手動操作を1回取り消せます。別の変更後などは使えません。

同じ名前で手動追加しても別人扱いになります。再参加時に同じ参加回数を引き継ぎたい場合は、同じ参加者IDを指定してください。
待機列と回数は自動保存されます。

■ OBSの見た目を変える
上部の「設定」で編集し、黄色の「保存してOBSに反映」を押します。
編集だけではOBSに反映されません。

・配置セットで縦向き／横向きを切り替えます。縦横で幅・高さは共通なので、切替のたびにOBS設定を変更する必要はありません。
・行編集欄でEnterを押すと改行・空行を追加でき、Backspaceで削除できます。
・[NOW1]などは参加者名が自動更新される欄です。
・[受付]や[NOW見出し]を削除すると、その文字は表示されません。空白も詰めたい場合は改行ごと削除します。
・横向きで列全体を空欄にすると、その列も詰まります。
・「OBSの文字色（一括）」で受付・見出し・参加者名・待機人数の文字色を変更できます。保存後は次回も同じ色です。
・文字サイズとフォントは一括／項目別で変更できます。
・長い名前は末尾を省略し、行が多い場合は文字を自動縮小します。
・表示名はYouTubeアカウント名、申告名、その両方から選べます。

「設定をリセットする」は確認後に表示設定を初期化します。

■ 概要欄の案内文をコピーする
管理画面下部の「その他（設定・バックアップ）」を開きます。
「概要欄コピペ用」の文章は自由に編集できます。
「文章を保存」で次回用に保存し、「文章をコピー」で配信の概要欄へ貼り付けます。
コピーだけでは保存されません。

■ コメントによる参加について
管理画面の「YouTubeコメント受信」で、配信URLとYouTube Data API v3のAPIキーを入力し「コメント受信を開始」を押します。
「受信中」を確認し、参加受付を開始してからコメントしてください。接続前の古いコメントは反映しません。約10秒以上の遅延があります。
APIキーは停止・終了で破棄されます。再接続時は入力し直してください。公開ライブ配信向けで、Google CloudでAPIの有効化が必要です。
通信障害は最大5回再接続し、利用上限・配信終了・権限エラーの場合は理由を表示して停止します。上限やエラー時は手動追加を使ってください。
Google Cloud: https://console.cloud.google.com/apis/library/youtube.googleapis.com
APIの制限はYouTube Data API v3を指定します。ブラウザ参照元制限付きキーは使えません。
公式APIでハンドルが得られない場合は表示名を使います。

受信中に使えるコメント：
参加希望
参加希望 『◯◯』
参加辞退
参加を辞退

『』内の名前は最大32文字で、申告名として登録されます。
OBSに出す場合は、名前表示設定で申告名を含む方式を選びます。
状態変更後は設定した秒数の間、連続操作が制限されます（初期値40秒）。設定画面の「コメントの連続操作制限」で0～3600秒に変更し、「制限時間を保存」を押します。0秒は制限なしです。現在の制限にも元の操作時刻を基準に適用し、再起動・バックアップ後も設定を引き継ぎます。参加希望の再送信は待機列の最後尾への移動になるため、名前変更は配信者に依頼してください。

■ 対戦した参加者の履歴
管理画面の「対戦した参加者の履歴」を開き、「一覧を更新」で確認します。
「次の対戦へ」を押すと、直前のNOWを記録します。最後の対戦後も押してください。
同じIDは1人としてまとめ、最初に対戦した順に並びます。同じ対戦の3人はNOWの並び順です。
名前は最後に記録した対戦時の表示名、回数はその配信で実際に記録した対戦数です。
「一覧をコピー」で概要欄などに貼り付けられます。
次の配信では名前を入力し「新しい配信の履歴を開始」を押します。以前の履歴は選択欄から確認できます。
配信URLでは自動で区切りません。待機列や累計参加回数は変更しません。
履歴は自動保存・バックアップに含まれます。「直前の操作を戻す」で対戦を戻すと履歴も戻ります。
全リセットで履歴も消えます。上限は100配信、1配信1万人です。
この機能を追加する前の参加順は復元できません。YouTubeはチャンネルID、手動追加は指定した参加者IDで同一人物を判定します。

■ バックアップと終了
「その他」の「バックアップを保存」でデータをJSONに保存できます。
復元は現在のデータを上書きします。先に現状のバックアップを保存してください。
フォントファイル本体はJSONに含まれないため、別PCでは再登録が必要です。

配信終了後は「アプリを終了」→「終了する」を押します。
「受付を終了」は参加受付だけを止める操作です。

■ アプリを削除する
本体だけを削除する場合：アプリを終了し、展開したフォルダーを削除します。保存データは残ります。

保存データも削除する場合：
必要なバックアップを保存し、アプリを終了した後、展開フォルダーでPowerShellを開いて以下を実行します。

& '.\参加型整列プラグイン.exe' --uninstall-data

待機列・回数・設定・取り込んだフォント等は元に戻せません。
処理が正常に終了した後、展開フォルダーを削除します。
OBSやEdgeの設定、共有ランタイムは削除しません。自分で保存したバックアップや、OBSへ追加したブラウザソース・ドックは必要に応じて自分で削除してください。

■ 困ったとき
・「Failed to resolve Python.Runtime.Loader.Initialize」が出る：ダウンロードしたDLLがWindowsでブロックされている場合があります。配布元を確認したZIPの「プロパティ」で「許可する」を適用し、別の新しいフォルダーへすべて展開して起動してください。ZIPだけを許可しても、展開済みファイルには反映されません。
・起動しない：ZIPをすべて展開したか、_internalが残っているか、WebView2が利用できるかを確認します。
・OBSに出ない：アプリが起動しているか、表示URLとソースのサイズ・表示状態を確認します。
・変更が反映されない：「保存してOBSに反映」を押します。
・参加コメントが反映されない：YouTubeコメント受信が「受信中」か確認します。受付状態と設定した連続操作制限も確認してください。

このアプリは未署名です。発行元の確認画面が出る場合があります。配布元を確認し、組織の実行制限がある場合は管理者へご相談ください。
実際のYouTube配信での受信、OBSとEdgeの長時間併用、クリーンPC、すべての表示倍率での動作確認は未実施です。

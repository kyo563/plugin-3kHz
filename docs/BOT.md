# 共通Botのお知らせ（わんコメ版0.1.5）

利用者ごとのBotアカウントやGoogle Cloud設定、OAuthクライアントJSONは不要です。コメント取得はわんコメ、待機列・OBS表示は既存Pythonアプリ、Bot投稿は固定の共通バックエンドで行います。

## 利用開始

1. @JoinQueueBotを配信チャンネルのモデレーターに登録します。
2. 設定画面の「Bot設定」タブから「配信チャンネルを接続」。認証リンクを通常ブラウザーで開き、照合番号を確認して配信者自身のチャンネルを認証します（Bot用OAuthではありません）。認証待ちの画面が表示されている間、最大10分間・最短10秒間隔で結果を自動確認します。通信失敗時は60秒待ちます。「認証結果を確認」で手動確認も可能です。
3. わんコメに接続している対象配信を確認し、通知を選んで「Botを起動」。変更した通知設定の保存・投稿先の接続確認・起動をまとめて行います。接続確認だけの操作とテスト投稿は任意です。

次回以降は有効なチャンネル認証と通知設定を再利用し、わんコメの接続先を確認して「Botを起動」します。再起動・配信変更後の自動起動は行いません。

認証途中のエラーは「認証を再開・やり直す」で既存接続を確認し、必要な場合だけ認証を再開します。それでも進めない場合や認証済みチャンネルを選び直す場合は「認証し直す」を押し、確認画面で「接続を解除して認証し直す」。接続解除成功後だけ新しい認証を開始します。Googleの読み取り専用許可も解除するため、同じGoogleアカウントの他のチャンネル・端末へ影響する場合があります。待機列・履歴・通知・表示設定は保持し、再認証してもBotは自動起動しません。通信失敗時はPC内のキーを勝手に削除せず、状態確認・再試行を可能にします（サーバーでの解除結果が不明な場合もあります）。

サーバーが運営側で停止中の場合は起動できません。アプリを配布しただけでサーバーは有効になりません。

## 3種類の通知

- 「次の対戦へ」で新しいNOW全員を1コメントで呼び出します。3名未満なら実在する人数だけ。初回のNOW補充・参加受付・辞退・完了のお礼は投稿しません。
- @JoinQueueBotへの呼びかけに、その送信者本人の待機順位・待機グループを返信します。NOWには「現在参加中です」、未登録には専用の返答をします。待機順はNOWを除き、NEXTの1～3番目を第1グループ、4～6番目を第2グループとして毎回数え直します。通算の対戦回数は返信のグループ番号に使いません。次の対戦へ進んだ際のNOW呼び出し通知は従来どおりです。
- Bot稼働中に15分または30分ごと、NOWを除く待機人数と待機グループ数（3名で切上げ）を案内します。受付を閉じていてもBot稼働中なら案内します。

各通知は個別チェックボックスで切り替え、「Bot設定を保存」で反映します。初期は3つともオン、間隔は30分。旧10分設定は30分へ移行します。全てオフでも待機列操作・OBS表示は変わりません。
定期案内の再オン・間隔変更時はそこから計り直します。起動直後・スリープ復帰直後の追送は行いません。

## 保存と安全対策

- 共通BotのGoogle秘密はPCへ配布・取得しません。旧版のGoogle認証データは読み込み・送信・削除せず、新方式から参照しません。旧版のGoogle認可が不要になった場合は、本人がGoogle側で解除してください。
- 接続キーと認証途中のリンク・照合番号・期限をWindows DPAPIで暗号化して専用bot.sqlite3へ保存。通常のJSONバックアップには含めません。WindowsユーザーやPCが変わった場合は再接続が必要です。
- 設定はshared_settings、端末キーはshared_device、認証途中の状態はshared_pairingへ保存。既存の待機列DB、フォント、履歴、プラグインUID、WaitingListAppOneComme保存先は変更しません。
- 再起動時は常にBot停止。配信変更・接続切断でも停止し、再起動を要求します。
- 同じ配信で稼働中に再度起動しても、タイマー・未送信キューは変更しません。起動ボタンも稼働中は無効です。
- 名前は投稿用だけ安全な文字・長さに整形します。長すぎるハンドルは別人への誤メンションを防ぐため途中で切って使いません。単発の形式エラー・期限切れ・重複衝突はその通知だけを破棄し、認証障害・結果不明などは停止します。
- Botの設定・保存DBを読めないときは元データを保持してBotだけ停止し、待機列・OBSは起動します。読めない状態で設定を上書き・自動初期化しません。
- 同一人物への返信は60秒に1回。投稿は最短10秒間隔、待機通知は最大20件・60秒で失効。設定変更・停止で未送信分を破棄します。サーバー側でも利用者・チャンネル・全体制限を適用します。
- 投稿失敗・結果不明時は自動再送しません。待機列操作は成功していても通知が失敗する場合があります。既に送信中の投稿は取り消せません。
- 接続解除は確認チェック必須。サーバーで失効できないときはキーを保全します。キーを持たない状態での開始拒否が確定した場合だけ安全に作り直せます。

## 検証状況

認証途中の再起動・通信失敗からの復旧仕様とサーバー／クライアントの配置順序は[BOT_AUTH_RECOVERY.md](BOT_AUTH_RECOVERY.md)を参照してください。

共通Botの認証が期限切れの場合は、運営者の再認証が必要と表示します。
配信者自身の再接続では直りません。通信失敗とは区別し、通知を自動再送しません。
運営者の更新手順と現在の検証状態はgoogle-oauth-review/shared-bot-renewal.txtを参照してください。

模擬サーバーによる通知・接続・停止・保存のテスト済み。実わんコメのコメント受信、実Googleによる配信者認証、YouTube実投稿、OBS実機操作は未検証です。既存の独立版1.1.3と過去のリリース・タグ・配布物は変更しません。
0.1.2の番号はユーザー指定です。過去の1.0.0/1.1.0より数値が小さいため、更新は手動でプラグインを無効にしてからフォルダを交換してください。

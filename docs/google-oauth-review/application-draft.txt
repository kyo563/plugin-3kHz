Application description (English submission draft)
JoinQueue is a Windows plugin for OneComme that helps YouTube livestream
creators manage a participant queue and display it in OBS. OneComme supplies
incoming comments; JoinQueue does not retrieve YouTube chat messages itself.
An optional centrally operated YouTube bot posts three types of notifications:
calling the next group, replying with a viewer's queue position when addressed,
and periodically announcing the waiting participant and group counts.
Creators independently connect their own channels and register @JoinQueueBot
as a moderator. They do not create bot accounts or OAuth clients. The initial
public service targets active public YouTube livestreams. Members-only
broadcast posting has not been verified and is not promised.

Requested scope: https://www.googleapis.com/auth/youtube.readonly
Audience: creators connecting their own streaming channels.
Purpose: call channels.list(part=id, mine=true) on the server after OAuth
consent to verify which YouTube channel the creator controls. Bind the verified
channel ID to the plugin's device connection so requests cannot target a
channel merely claimed by the client. This scope does not post messages.
The creator's Google access token is used for this lookup and is not retained
after the callback. No creator refresh token is requested (access_type=online).
OpenID profile or email alone does not prove control of a YouTube channel,
including a Brand Account channel. No creator write scope is requested.

Requested scope: https://www.googleapis.com/auth/youtube.force-ssl
Audience: the service operator authenticating the dedicated @JoinQueueBot
channel; not creators connecting their streaming channels.
Purpose: server-side liveChatMessages.insert for the optional notifications.
Read-only access cannot insert messages. This scope is supported by the
official insert endpoint; the code does not upload or delete videos, delete
comments, or perform moderation actions. channels.list(mine=true) verifies
the authenticated bot identity. videos.list verifies the target video's owner,
live status and activeLiveChatId before posting. Bot refresh credentials are
encrypted in server storage and never distributed with the plugin.
Operator authorization is separate from creator authorization, although the
current implementation uses the same configured Google OAuth client.

Implementation-grounded data notes for the privacy policy
- Queue, participation history, declared names, received OneComme memo and
  appearance preferences are stored locally on the creator's PC.
- The server receives the connected channel ID, target video ID, notification
  template and its variables (which can contain viewer handles/display names,
  queue positions, groups and counts). It needs these to post to YouTube.
- The full incoming chat history, OneComme memos and font files are not sent
  to the shared bot backend. The backend does not fetch incoming comments.
- Notification text is rendered transiently and sent to YouTube. The SQL
  posting ledger stores IDs, timestamps, hashes and delivery results, not
  full notification bodies. Posted text appears in the creator's live chat.
- Server connection records include verified channel IDs, device identifiers,
  hashed device credentials and revocation information. The local device
  credential is protected using Windows DPAPI.
- Disconnect revokes the server connection and removes the local connection
  credential. It does not currently erase all server connection or post records.
- Unsuccessful expired pairing records are cleaned during subsequent pairing
  creation. Server erasure and bounded retention are implemented and tested,
  but the user explicitly declined enabling them in production on 2026-10-01.
  BOT_DATA_LIFECYCLE_ENABLED remains disabled. Do not claim that production
  records are erased automatically or that the deletion UI is already released.
- Network requests are processed by Cloudflare and Google/YouTube. Admission
  control uses hashed source identifiers rather than storing raw IP addresses
  in the application SQL ledger. Do not promise that infrastructure providers
  retain no network metadata.

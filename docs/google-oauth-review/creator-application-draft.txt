Scope justification — intended isolated implementation, NOT yet production
JoinQueue is a Windows participant-queue plugin for OneComme. Creators connect
their own YouTube channels to an optional centrally operated notification bot.
The server calls channels.list(part=id,mine=true) after consent to verify the
creator's channel ID and bind it to their authenticated device. A client-supplied
channel ID, public profile or email cannot prove control of a YouTube channel,
including a Brand Account. youtube.readonly is the narrowest supported scope
for this lookup. We request offline access and encrypt the refresh credential
on our server only to recheck continuing authorization and revoke the grant
when disconnected. Access tokens are transient, never returned to the plugin.
Scheduled checks also re-fetch channels.list(mine=true) to refresh ownership
data itself; refreshing an OAuth access token alone is not a data refresh.
This scope never posts as the creator or fetches incoming live chat. Incoming
comments come from OneComme. Bot posting uses a separately authorized service
Bot in another Google Cloud project; its credentials never reach creators.

Additional explanation — central Bot and separation
The dedicated @JoinQueueBot account is authorized by the operator under
joinqueue-bot-dev, not by each creator. Its write credential is server-only.
The current creator project contains no Bot operator OAuth client or write
scope. Revoking one creator's grant cannot revoke the Bot grant in the other
project. Google revocation may affect multiple creator Brand Account grants
belonging to the same Google account within this creator project; we explain
that reauthorization may be necessary. Distinct creators cannot select each
other's connection or route messages to a channel they have not verified.

Data disclosure to align before submission
Queue/history, OneComme memos, display preferences and fonts remain local.

readonly refresh credentials, authorization dates and notification metadata.

persist full notification bodies in the application posting ledger. Notifications
sent to YouTube become visible in the destination live chat. Cloudflare hosts
the server, GitHub Pages the public site, and Google/YouTube the OAuth/API.

the dedicated public service email identify the operator in public materials.

Intended retention — implemented locally, NOT enabled in production
Authenticated plugin status/connection checks and validated Bot requests extend
the channel's last-use timestamp. New creator connections expire after 90 days
without such use. Server alarms or automatic Google refresh checks do not count
as user activity. Ownership data is separately re-fetched daily; connections
whose data cannot be refreshed within 29 days are stopped. Posting-ledger data
is retained for 29 days, not 90. Explicit disconnect/deletion and Google-side
revocation are handled independently, not postponed until inactivity expiry.
These claims must not be submitted as deployed behavior until the rollout,
real grant tests and deletion-operation approval are complete.
